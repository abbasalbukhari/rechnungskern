About {{ s.site_name }}

{{ s.site_name }} is an independent project by {{ name }}{% if title_line %}, {{ title_line }}{% endif %}. It creates and validates e-invoices according to EN 16931 – free of charge and without storing any data.

Why this project exists

Germany has been phasing in mandatory electronic invoicing for B2B since 2025. Large companies solve this with their ERP systems; small businesses, freelancers and tradespeople are often left with a PDF that legally is not an e-invoice. The goal of {{ s.site_name }} is simple: enter invoice data, get a compliant ZUGFeRD/Factur-X PDF or XRechnung XML back – in the browser or via API – and be able to check any e-invoice against the same rules that authorities apply.

Design decisions

  • No data retention. Invoice data is processed in memory and discarded once the response is delivered. This is not a feature toggle but the architecture: there is no database.
  • Compliance is verified, not assumed. Every XML is checked against the official schema; the EN 16931 and XRechnung Schematron rules as well as PDF/A-3 are checked with the Mustang validator, and the test suite contains negative tests that prove the validator catches violations.
  • Amounts are calculated server-side with decimal arithmetic and the rounding rules of the standard (BR-CO-*), so line, document and VAT totals are always consistent – including price discounts, line and document level allowances and charges.
  • Boring, proven technology. Python, FastAPI, WeasyPrint (HTML to PDF/A-3), drafthorse (CII XML), Caddy for TLS, Docker for deployment. No JavaScript framework on the site; the invoice editor is plain JavaScript that keeps your entries in your own browser.

Über {{ s.site_name }}

{{ s.site_name }} ist ein unabhängiges Projekt von {{ name }}{% if title_line %}, {{ title_line }}{% endif %}. Es erstellt und prüft E-Rechnungen nach EN 16931 – kostenlos und ohne Speicherung von Daten.

Warum es dieses Projekt gibt

Seit 2025 wird die elektronische Rechnung im B2B-Bereich in Deutschland schrittweise Pflicht. Große Unternehmen lösen das über ihre ERP-Systeme; kleine Betriebe, Selbstständige und Handwerker stehen oft mit einer PDF da, die rechtlich keine E-Rechnung ist. Das Ziel von {{ s.site_name }} ist einfach: Rechnungsdaten eingeben, eine konforme ZUGFeRD/Factur-X-PDF oder XRechnung-XML zurückbekommen – im Browser oder per API – und jede E-Rechnung gegen dieselben Regeln prüfen können, die auch Behörden anwenden.

Entscheidungen hinter dem Dienst

  • Keine Datenspeicherung. Rechnungsdaten werden im Arbeitsspeicher verarbeitet und nach der Auslieferung verworfen. Das ist keine Einstellung, sondern die Architektur: Es gibt keine Datenbank.
  • Konformität wird geprüft, nicht angenommen. Jede XML wird gegen das offizielle Schema validiert; die Schematron-Regeln von EN 16931 und XRechnung sowie PDF/A-3 prüft der Mustang-Validator. Die Testsuite enthält Negativtests, die belegen, dass der Validator Verstöße tatsächlich erkennt.
  • Beträge werden serverseitig berechnet mit Dezimalarithmetik und den Rundungsregeln der Norm (BR-CO-*), damit Positions-, Rechnungs- und Steuersummen immer zusammenpassen – auch bei Preisnachlässen, Positions- und Rechnungsrabatten und Zuschlägen.
  • Bewährte Technik statt Modeerscheinungen. Python, FastAPI, WeasyPrint (HTML zu PDF/A-3), drafthorse (CII-XML), Caddy für TLS, Docker für den Betrieb. Kein JavaScript-Framework; der Rechnungs-Editor ist einfaches JavaScript, das Ihre Eingaben in Ihrem eigenen Browser behält.
